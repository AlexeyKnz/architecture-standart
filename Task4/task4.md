### Название задачи: Интеграция кол-центров с системой ставок
### Автор: Архитектор
### Дата: 2024.03.20

### Функциональные требования

| № | Действующие лица или системы | Use Case | Описание |
|:-:|:-----------------------------|:---------|:---------|
| 1 | Оператор кол-центра | Консультация по текущим ставкам | Доступ к актуальным ставкам в системе CRM |
| 2 | Оператор партнерского кол-центра | Консультация по текущим ставкам | Доступ к актуальным ставкам через файлы |
| 3 | Администратор | Управление передачей файлов | Настройка и мониторинг передачи данных партнеру |
| 4 | Система ставок | Генерация файлов для партнера | Автоматическое создание файлов с актуальными ставками |

### Нефункциональные требования

| № | Требование |
|:-:|:----------|
| 1 | Обновление ставок в реальном времени (для внутреннего кол-центра) |
| 2 | Ежедневное обновление файлов для партнера |
| 3 | Безопасная передача файлов (SFTP) |
| 4 | Совместимость с форматами файлов партнера |
| 5 | Резервный канал передачи данных |

### Решение

**Диаграммы:** 
- `call_center_context.png` - Диаграмма контекста интеграции
- `Компоненты системы.png` - Диаграмма компонентов

**Архитектурные решения:**
1. REST API для внутреннего кол-центра - прямой доступ к сервису ставок
2. SFTP-сервер для обмена файлами с партнерским кол-центром
3. Ежедневная автоматическая генерация файлов с актуальными ставками
4. Механизм верификации полученных файлов

### Альтернативы

**Альтернатива 1:** Прямое API для партнера
- *Недостатки:* Нет технической возможности у партнера
- *Риски:* Нарушение требований безопасности

**Альтернатива 2:** Ручная отправка файлов
- *Недостатки:* Высокая нагрузка на персонал, риск ошибок
- *Ограничения:* Не масштабируется при росте нагрузки

**Недостатки, ограничения, риски**

1. **Задержка данных:** Партнер получает данные с задержкой до 24 часов
2. **Безопасность:** Риски при передаче файлов по SFTP
3. **Мониторинг:** Сложность отслеживания доставки файлов
4. **Формат данных:** Зависимость от форматов файлов партнера
