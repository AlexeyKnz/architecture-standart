# Пояснения к дорожной карте (RoadMap) интеграции кол-центров

## Общий подход

Дорожная карта разработана на 6 месяцев с учетом поэтапного внедрения изменений. Используется итеративный подход, позволяющий начать с быстрых задач (REST API для внутреннего кол-центра) и постепенно переходить к более сложным интеграциям (работа с внешним партнером).

## Детализация этапов

### Месяц 1-2: Базовая функциональность (Сервис ставок)

**Задачи:**
- `REST API разработка` - создание API для реального доступа к ставкам
- `Генерация файлов` - разработка механизма экспорта в форматах партнера
- `SFTP настройка` - развертывание безопасного канала передачи

**Обоснование:** Начинаем с ядра системы - сервиса ставок, так как это основа для всех последующих интеграций.

### Месяц 3: Интеграция с внутренним кол-центром

**Задачи:**
- `Интеграция с API` - подключение CRM к новому API
- `UI для ставок` - разработка интерфейса для операторов
- `Обучение операторов` - подготовка персонала к работе с новой системой

**Обоснование:** Внутренний кол-центр имеет приоритет, позволяет отработать процессы перед интеграцией с партнером.

### Месяц 4: Работа с партнерским кол-центром

**Задачи:**
- `Настройка SFTP приема` - подготовка инфраструктуры у партнера
- `Интеграция с системой` - адаптация внутренних процессов партнера
- `Тестовые передачи` - отладка механизма обмена файлами

**Обоснование:** Наиболее сложный этап из-за работы с внешней организацией и ограничений по технологиям.

### Месяц 5-6: Внедрение и стабилизация

**Задачи:**
- `Пилотная эксплуатация` - ограниченный запуск с мониторингом
- `Полное внедрение` - масштабирование на все отделения
- `Мониторинг и поддержка` - обеспечение стабильной работы

**Обоснование:** Поэтапное внедрение снижает риски и позволяет оперативно исправлять проблемы.

## Критические зависимости

1. **Технологические:**
   - Готовность SFTP-инфраструктуры к месяцу 2
   - Совместимость форматов файлов с системами партнера

2. **Организационные:**
   - Участие бизнес-представителей партнера в настройке процессов
   - Выделение ресурсов на обучение операторов

3. **Временные:**
   - Согласование форматов данных с партнером до начала разработки
   - Планирование тестовых окон для интеграции

## Метрики успеха

| Метрика | Целевое значение | Периодичность измерения |
|---------|------------------|-------------------------|
| Availability REST API | 99.9% | Ежечасно |
| Время отклика API | < 100 мс | Ежедневно |
| Частота обновления файлов | 24 часа | Ежедневно |
| Полнота данных в файлах | 100% | При каждом обновлении |
| Задержка доставки файлов | < 1 часа | Ежедневно |

## Риски и mitigation

| Риск | Вероятность | Impact | Меры mitigation |
|------|-------------|--------|-----------------|
| Задержки с партнером | Высокая | Высокий | Регулярные sync meetings, эскалация |
| Проблемы с форматами данных | Средняя | Средний | Раннее тестирование, гибкие конвертеры |
| Перегрузка SFTP | Низкая | Высокий | Мониторинг нагрузки, автоматическое scaling |
| Сопротивление операторов | Средняя | Средний | Раннее вовлечение, training, обратная связь |

## Целевое состояние (12 месяцев)

К концу года планируется достичь:
- Полной автоматизации процесса обмена данными
- Реального времени обновления ставок для всех каналов
- Расширенной аналитики использования ставок
- Интеграции с дополнительными партнерами
- Self-service портала для партнеров
